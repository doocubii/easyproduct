# 백엔드 아키텍처: [서비스 이름]

> 이 문서는 백엔드의 **시스템 구성·인증 방식·외부 연동·횡단 규약·비기능 요건**에 관해 다른 어떤 문서보다
> 우선하는 기준(SSOT)이다. 다만 **데이터의 뜻과 필드 구성은 데이터 모델 문서가, 제품 규칙은 정책서가,
> 화면·기능의 범위는 화면·기능 구조(IA)가** 여전히 기준이다 — 이 문서는 그것들을 배치·확정할 뿐 다시 정의하지 않는다.
>
> 이 문서를 고칠 때는 아래를 지킨다:
> - ID(`BEARCH.mod.*`·`BEARCH.ext.*`)는 한 번 부여하면 바꾸지 않는다. 없앨 때는 지우고, 뜻이 바뀌면 새 ID를 만든다.
> - 산문을 고치면 아래 JSON 블록을 **산문 기준으로 다시 생성**한다(JSON을 손으로 고치지 않는다).
> - 결정을 바꿀 때는 **왜 바꾸는지**를 함께 적는다. 이유가 사라지면 다음 사람이 되돌릴 수 없다.
> - **언어·프레임워크는 이 문서가 정하지 않는다.** 조각의 역할과 경계가 설계이고, 무엇으로 구현할지는 계약 밖이다.
>
> **함께 보는 문서**: 인터페이스 계약 `backend-interface.md` · 저장 설계 `backend-storage.md` · 데이터 모델 `data-model.md` · 정책서 `policy.md`

## 기계용 블록

아래 블록은 위 산문의 **미러**다. 산문이 원본이며, 산문을 고치면 이 블록을 다시 생성한다.
**손으로 고치지 않는다.**

```json backend.system
{
  "system": {
    "name": "[시스템 이름]",
    "style": "modular-monolith",
    "desc": "[왜 이 모양인지]",
    "boundaries": ["[책임지지 않는 것]"]
  },
  "modules": [
    {
      "id": "BEARCH.mod.[이름]",
      "name": "[이름]",
      "kind": "api",
      "responsibility": "[책임]",
      "owns": ["BESTORE.[저장소]"],
      "dependsOn": ["BEARCH.ext.[연동]"],
      "scaling": "[늘리는 방법]"
    }
  ],
  "authModes": [
    {
      "mode": "[모드]",
      "desc": "[무엇을 요구·차단]",
      "mechanism": "[유지 메커니즘]",
      "actor": "account",
      "lifetime": "[수명]",
      "policy": "POL.[도메인].[규칙]"
    }
  ],
  "integrations": [
    {
      "id": "BEARCH.ext.[이름]",
      "name": "[대상]",
      "purpose": "[목적]",
      "failureMode": "[죽으면 무엇을 하나]",
      "direction": "outbound",
      "confirmed": false
    }
  ],
  "crossCutting": [
    { "topic": "[주제]", "decision": "[결정]", "why": "[이유]" }
  ]
}
```

### 이 블록으로 소프트웨어가 자동 점검할 수 있는 것

- **ID 형식** — `BEARCH.mod.*`·`BEARCH.ext.*`가 규칙대로인지, 전역 유일한지.
- **죽은 링크** — `owns`가 가리키는 `BESTORE.*`가 저장 설계에 실재하는지, `dependsOn`이 가리키는
  조각·연동이 실재하는지.
- **인증 등기부** — 인터페이스 계약의 모든 `auth.mode`가 여기 `authModes`에 실재하는지.
- **빠진 내용** — 조각에 책임이, 외부 연동에 실패 처리가 비어 있지 않은지.

의미가 맞는지(이 조각 분할이 타당한가·이 인증 방식이 이 제약에 맞는가)는 소프트웨어가 판단할 수 없다 —
사람 또는 LLM의 풀 리뷰 몫이다.
