# 논리 스키마 — 개념을 물리로 옮길 때의 갈림길

> 이 문서는 `easyproduct-backend` 스킬의 **5단계(물리 스키마)**가 참고하는 지식 문서다. DB 제품을 고르는
> 문서가 아니라, **개념 데이터 모델을 테이블로 옮길 때 무엇을 결정해야 하는지**를 정리한 것이다.

## 첫 번째 원칙: 개념과 다르면 이유를 적는다

개념 데이터 모델은 **사람이 이해하는 단위**로 쓰였고, 물리 스키마는 **저장소가 잘 다루는 단위**로 쓰인다.
둘이 달라지는 것은 결함이 아니라 정상이다. **결함은 다른데 이유가 없는 것이다** — 그러면 다음 사람이
"실수인가, 뜻이 있나"를 알 수 없어 되돌리지도 유지하지도 못한다.

`origin` 네 갈래로 표시한다: `concept`(1:1) · `split`(하나를 여럿으로) · `join`(여럿을 잇는 연결 테이블) ·
`backend-only`(개념에 없는 것). **`concept`이 아니면 `divergence`를 반드시 적는다.**

## 논리 타입 — 제품 이름을 쓰지 않는다

| 논리 타입 | 무슨 뜻 | 주의 |
|---|---|---|
| `uuid` | 추측할 수 없는 식별자 | 아래 "식별자 전략" 참고 |
| `string` | **길이 상한이 있는** 문자열 | 상한에 근거가 있어야 한다(이메일 320자 등). 근거 없이 255를 쓰지 않는다 |
| `text` | 상한 없는 문자열 | 목록 조회에 섞이면 느려진다. 본문·설명처럼 통째로 읽는 것만 |
| `integer` / `bigint` | 정수 | 개수·금액(최소 단위). 금액에 `decimal`을 쓰지 않는 이유는 아래 |
| `decimal` | **정확한** 소수 | 자릿수·소수점을 함께 적는다. 비율·세율처럼 소수가 뜻을 갖는 값에만 |
| `boolean` | 참·거짓 | 나중에 세 번째 상태가 생길 낌새가 있으면 처음부터 열거로 |
| `timestamp` | **시간대를 포함한** 시각 | 시간대 없는 시각을 쓰지 않는다 — 정산·감사에서 반드시 문제가 된다 |
| `date` | 날짜만 | 시각이 의미 없는 것(청구 기간 등) |
| `enum` | 정해진 값 집합 | 반드시 `enums`에 선언하고 참조 |
| `json` | 구조를 통째로 담는 값 | 아래 "언제 통째로 담나" |
| `binary` | 바이트 | 큰 것은 객체 저장소로 빼는 게 낫다 |

**제품이 정하는 것과 섞지 않는다** — 실제 타입 이름·문자셋·콜레이션·저장 엔진은 마이그레이션 몫이다.

## 제품 결정처럼 보이지만 논리로 끌어올려야 하는 것

이걸 물리에 맡기면 **제품을 바꿀 때 동작이 조용히 달라진다.**

- **문자열 비교가 대소문자를 구분하나** — 이메일 유일성이 여기 걸린다. 제품 기본값이 서로 다르다.
  `"이 컬럼의 유일성은 대소문자를 구분하지 않는다"`를 논리에 적는다.
- **빈 문자열과 없음이 같은가** — 어떤 제품은 같게 다룬다. `nullable`을 적을 때 빈 문자열을 허용하는지도
  함께 정한다.
- **정렬 순서** — 한글·특수문자 정렬이 제품마다 다르다. 목록의 정렬 키가 사람 눈에 보이는 순서라면 적는다.
- **금액** — 소수로 다루면 합계가 어긋난다. **최소 단위 정수 + 통화**를 권한다.
- **시각의 정밀도** — 초·밀리초·마이크로초가 제품마다 다르다. 같은 순간에 두 행이 들어올 수 있는
  곳(이력·감사)에서는 정밀도가 곧 순서 판별력이다.

## 식별자 전략

| 갈래 | 좋은 점 | 대가 |
|---|---|---|
| 순번(자동 증가) | 작고 정렬이 자연스럽다 | **개수가 밖으로 샌다**(가입자 수·주문 수). 여러 저장소에 나눠 담기 어렵다 |
| 임의 식별자(UUID 계열) | 새지 않고, 만드는 쪽이 미리 정할 수 있어 분산에 유리 | 인덱스가 커지고, 완전 무작위면 삽입 위치가 흩어져 느려진다 |
| 시간순 정렬되는 임의 식별자 | 위의 삽입 문제를 줄이면서 새지 않는다 | 만든 시각이 대략 드러난다 |

**밖으로 나가는 식별자와 안에서 쓰는 키를 나눌 수도 있다**(내부는 순번, 외부는 임의 값). 다만 그러면
컬럼이 둘이 되고 조회가 늘어난다 — 셀 수 있으면 곤란한 데이터가 실제로 있을 때만 값을 치른다.

## 개념 하나가 테이블 여럿이 되는 경우 (`split`)

- **수명·접근 빈도가 다를 때.** 비밀번호 해시는 계정과 함께 읽히지 않고, 잘못 흘리면 피해가 다르다 —
  갈라 두면 "계정을 읽는 코드"가 자격 증명을 실수로 들고 다니지 않는다.
- **하나가 무한히 자랄 때.** 이력·로그는 부모와 함께 읽히지 않고 계속 쌓인다.
- **선택 항목이 대부분 비어 있을 때.** 다만 이건 이득이 작으니 신중히.

**갈랐으면 두 테이블이 함께 만들어지고 함께 지워지는지**를 정해야 한다 — 한쪽만 남는 상태를 무엇이 막나.

## 개념에 없지만 물리에 반드시 있는 것 (`backend-only`)

개념 모델은 **사용자가 보는 것**만 담는다. 아래는 개념에 없어도 거의 항상 필요하다.

- **감사 기록** — 누가·언제·무엇을 했나. 특히 운영자 행위(승인·반려·정지·환불)는 개념 모델에
  `reviewedBy` 같은 컬럼 하나로만 남는 경우가 많은데, **그것만으로는 나머지 행위를 담을 자리가 없다.**
- **스키마 이행 이력** — 마이그레이션 도구가 쓰는 것.
- **아웃박스** — 저장과 큐 발행을 한 트랜잭션으로 묶어야 할 때(저장 설계가 재구성으로 대신하기로 했으면 불필요).
- **연결 테이블** — 개념의 다대다 관계는 물리에서 반드시 테이블이 된다.

## 언제 통째로 담나 (`json`)

- **담아도 되는 것**: 밖에서 받은 응답 원문, 구조가 사용자마다 다른 설정값, 조회 조건이 되지 않는 부속 정보.
- **담으면 안 되는 것**: **조회·정렬·집계의 대상**, 다른 곳에서 참조하는 값. 통째로 담긴 값 안을
  뒤지기 시작하면 인덱스도 제약도 걸 수 없다.
- 개념 모델에서 `목록` 타입이라고 통째로 담을 이유가 되지 않는다 — **그 목록의 항목을 따로 조회하거나
  세어야 하면 테이블로 가른다.**

## 참조 무결성 — 걸 것인가

**기본은 건다.** 걸지 않으면 존재하지 않는 대상을 가리키는 행이 언젠가 반드시 생기고, 그때는 이미
어느 것이 진짜인지 알 수 없다.

| 삭제 동작 | 언제 |
|---|---|
| `restrict`(제한) | **기본값.** 지우려면 자식을 먼저 정리하게 만든다 |
| `cascade`(연쇄) | 자식이 부모 없이는 뜻이 없을 때만. **지우려던 것보다 많이 지운다**는 걸 항상 기억한다 |
| `set-null`(null화) | 관계가 끊겨도 행 자체는 남아야 할 때(작성자가 탈퇴해도 남는 기록 등) |

**걸 수 없는 경우**가 있다 — 한 컬럼이 여러 종류를 가리킬 때(`ownerType`+`ownerId` 같은 꼴), 또는
비-참조 값이 같은 칸에 섞일 때(`미설정`·`개인`). 그때는 외래키 대신 **애플리케이션 검증**으로 적고,
**"동시 요청에 뚫릴 수 있다"**는 사실을 함께 남긴다.

## 소프트 삭제와 파기

`status`에 "탈퇴"가 있으면 이미 소프트 삭제다. 그런데 개인정보 규정은 **파기**를 요구할 수 있다.
둘은 상충하므로 어느 쪽이 이기는지 정해야 한다.

흔한 절충: **행은 남기고 개인 식별 값만 지운다**(익명화). 이러면 참조 무결성이 깨지지 않으면서
개인정보가 사라진다. 다만 **무엇이 개인 식별 값인지**를 컬럼 단위로 정해 두어야 실행할 수 있다.

**법정 보존 대상**(거래 기록 등)은 다른 규칙이 적용되므로 같은 파기 규칙에 넣지 않는다.

## 열거값 — "등"을 없앤다

개념 모델은 `"활성/정지/탈퇴 **등**"`처럼 열어 두는 경우가 많다. **"등"이 남아 있으면 구현할 수 없다.**

- **값마다 뜻을 적는다.** 이름만으로는 `suspended`가 일시인지 영구인지 알 수 없다.
- **정책에서 값을 끌어낸다.** "경고 → 일시 정지 → 영구 정지" 같은 문장이 곧 값 집합이다.
- **상태 전이를 적는다.** 어디서 어디로 갈 수 있는지 적어 두지 않으면 아무 전이나 허용된다 —
  탈퇴한 계정이 활성으로 돌아가는 것도 막지 못한다.
- **표시 문구를 값으로 쓰지 않는다.** 값은 안정적이어야 하고 문구는 바뀐다.
- 값이 밖으로 나가면(API 응답) **인터페이스 계약의 `values`가 이 집합을 그대로 참조**한다 — 두 곳에서 따로
  정하지 않는다.
