# SDD 하네스 — 이 프로젝트의 규약

> 이 프로젝트는 **모든 제품 코드가 spec-kit 슬라이스(`specs/<slug>/`)에서 파생됐음**을 기계적으로 검사한다.
> 설정은 `sdd-policy.json` 하나이고, 검사기는 `<검사기 경로>`다. 사람이 읽을 규약만 여기 적는다.

## 1. 코드에 출처를 붙인다 (규칙 ①)

관장 대상 파일 앞부분에 **한 줄**:

```
<주석> @sdd <slug>          예: // @sdd 001-operator-console
```

정당한 예외는 **눈감지 말고 선언**한다:

```
<주석> @sdd:exempt <사유>    예: # @sdd:exempt 자동 생성 파일
```

## 2. 코드를 고치면 슬라이스도 고친다 (규칙 ②③)

- `specs/<slug>/`에 **`spec.md`·`plan.md`·`tasks.md`·`sources.json`**이 있어야 하고 비어 있으면 안 된다.
- 관장 파일이 바뀐 브랜치에서는 **그 슬라이스 폴더에도 변경**이 있어야 한다.
  포맷·기계적 리팩터는 커밋 트레일러로 면제한다:

```
SDD-Exempt: 포맷 변경만 (로직 변화 없음)
```

## 3. 상위 문서를 고치면 흐름을 태운다 (규칙 ④⑥)

**상위 문서** = `<정책의 upstreamDocs.globs>` (기획서·SSOT·헌법·CLAUDE.md 등).

- 상위 문서만 바뀌고 슬라이스가 하나도 안 바뀌면 **위반**이다(⑥).
  → 어느 슬라이스가 그 변경을 흡수하는지 재검토하고 흔적을 남긴다.
- 각 슬라이스는 `sources.json`에 자기 근거 문서를 **`version` + `contentHash`로 이중 핀**한다(④).
  - 상위가 **버전업**되면 → 재검토 후 핀 갱신.
  - 상위가 **버전업 없이 수정**되면 → 별도 위반으로 잡힌다. **상위 문서의 `version`을 먼저 올린다.**

## 4. spec을 고치면 상위와 대조한 기록을 남긴다 (규칙 ⑤⑦)

- `spec.md`·`plan.md`의 요구는 **상위 문서의 앵커를 근거로 참조**한다. 근거 없는 요구는
  "spec이 결정을 발명한 것"이므로 **먼저 상위 문서로 이관**한다(⑤).
- `spec.md`·`plan.md`를 고쳤으면 **`specs/<slug>/upstream-check.md`를 같은 변경에서 갱신**한다(⑦).
  `/speckit.analyze`를 돌려 그 출력과 근거 앵커·`checkedAt`을 기록한다.
  **판단은 사람/LLM이 하고, 하네스는 그 리뷰가 생략되지 못하게 한다.**

## 5. 검사 돌리기

```bash
<검사기 실행 명령> --full            # 전체 (verify·CI가 부르는 것)
<검사기 실행 명령> --changed <파일>  # 편집 직후 빠른 검사(훅)
<검사기 실행 명령> --full --json     # CI 파싱용
```

종료코드: `--full`은 `0` 통과(경고 있어도) · `1` 위반 · `2` 설정 오류.
`--changed`(훅)는 위반 시 **`2`** — 그래야 메시지가 에이전트 컨텍스트에 주입된다.

**CI 주의**: ③⑥이 `merge-base`를 쓰므로 **전체 히스토리**가 필요하다. 얕은 클론이면 검사가 HEAD~1로
후퇴하고 리포트에 그 사실이 뜬다. GitLab은 `variables: { GIT_DEPTH: 0 }`, GitHub Actions는
`actions/checkout` 의 `fetch-depth: 0`을 넣는다.
현재 모드: **`<mode>`** — `warn`이면 위반이 경고로만 보고된다(도입 중). 정리 후 `block`으로 바꾼다.

## 6. 이 검사가 보장하지 않는 것

**의례·공존을 강제할 뿐, 인과적 파생이나 의미 정합을 검증하지 않는다.** 태그만 붙이거나, 슬라이스를
형식만 고치거나, 핀 숫자만 갱신하면 통과한다. **기계 통과 ≠ 검증 완료** — 그 흔적이 히스토리에 남아
리뷰에서 보이는 것이 이 하네스의 효용이다. 최종 판단은 사람과 리뷰의 몫이다.
